# Identity Pulse roadmap — verified baseline and gated delivery

Updated 2026-09-26. Reviewed branch `main`, commit `3ba2626747a870c510162060fd6f3ba7849d07af`; working tree was clean before this planning update. Source, dependencies and governance instructions are unchanged. This is a plan, not a release announcement.

## Current capability and next executable work

The implemented product is a local read-only TypeScript CLI for Auth0 and Okta, with 59 catalog rule IDs (29/30), Markdown/HTML/JSON, report comparison, combined summaries and opt-in NIS2/ISO 27001/SOC 2 mappings. Findings, comparison semantics and mapping evidence have important limits: see [current evidence](ASSESSMENT-2026-09-26.md). Entra, Keycloak, AD, evidence packs, a remediation register and runtime session/token tests are not implemented. Existing combined summaries are theme grouping, not identity correlation.

**Exactly one active task: [045 — Restore trustworthy local and CI verification](active/045-verification-toolchain.md).** The first three engineering tasks are:

1. [045 — Restore trustworthy local and CI verification](active/045-verification-toolchain.md) — establish checks that can detect regressions; the current suite cannot start here, test type-check fails and lint masks failure.
2. [046 — Contain credentials and bound HTTP collection](backlog/046-http-origin-and-pagination-safety.md) — contain bearer credentials to approved HTTPS destinations and bound collection.
3. [047 — Preserve security configuration while removing secrets](backlog/047-semantic-redaction.md) — stop redaction from deleting the security settings that findings depend on.

After 045, independent ready engineering work can be scheduled in that priority order; the normal single-active-task workflow is unchanged. IDs are stable references, not a numeric execution sequence. **011 is backlog/blocked**, not the next task. Its missing prerequisites now include corrected controls, comparable assessments, manifest/source references, a register and scan-derived reviewed mapping evidence.

## First pilot versus later growth

- First supported customer pilot needs the M1 security/correctness gate, M2 validated/replayable outcomes, M3 minimal pack/register, and human-authorized reference validation in 064. Early interviews/demo review in 063 are not blocked by these gates and must be labeled exploratory.
- M3 uses local files, existing HTML/JSON and a JSON register. No DB, SaaS, dashboard, graph or CSV is a default prerequisite.
- Entra is the provisional next provider, scoped to administrative roles, authentication-policy coverage, enterprise applications and service principals. 065/066 decide whether to build; no expansion merely because earlier tasks finish.
- [067 — Choose AD or Keycloak only from committed pilot need](backlog/067-ad-keycloak-demand-evaluation.md) adds the previously missing AD discovery decision and keeps Keycloak 022/023 conditional on committed pilot need. Other provider research 024–032 stays visible with per-task activation criteria.
- 068 identity/access correlation, 069 federation and 070 session/token test operating model are deferred. 044 writes and 070 active tests require a separate explicit authorization/containment/recovery model; neither changes the current read-only CLI mandate.
- 033 storage, 035 baseline CI, 036 profiles, 037 activity trends, 038 user risk, 039 broad licensing advice, 040 AI, 041 DSL, 042 UI and 043 hosted multi-tenancy are demand-gated. Existing fail-on flags, bounded logs and environment calibration are not relabeled as unimplemented.

## Readiness and decisions

The existing status/folder convention remains `active`, `backlog`, `done`. Task `Readiness` is supplemental planning metadata: ready, blocked by unfinished tasks, human-dependent, or deferred pending activation. Dependencies list completion prerequisites; human-dependent research/process preparation may begin earlier where explicitly stated, but completion still requires evidence and reviewers. A completed dependency does not satisfy a separate human/activation requirement.

[Human decisions](HUMAN-DECISIONS.md) list owners by role and evidence needed; no people or customers have been invented. [Reconciliation](RECONCILIATION.md) accounts for every former task 001–044. [Assessment record](ASSESSMENT-2026-09-26.md) separates current checks, historical evidence and unverified integration/legal claims.
